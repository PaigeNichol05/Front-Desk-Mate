# Front Desk Mate update — October 17, 2026

Version **0.2.0** adds working fictional eligibility requests and encounter-linked blood-pressure/pulse observations to the existing local application. The goal remains one coordinated patient, clinician and billing workspace. This release is a development prototype, not an Epic-equivalent production EHR.

## What changed

| Area | Implemented behavior |
| --- | --- |
| Electronic eligibility foundation | Structured test requests, deterministic active/inactive/partial/exclusion/failure fixtures, separate eligibility/benefit/network/authorization/payment sections |
| Coverage review | Exact-context link to eligibility simulations, prominent professional-review requirement, existing manual evidence entry preserved |
| History and safeguards | Append-only attempts and staff reviews, fingerprints/provenance, effective/recheck dates, idempotent replay, retained failures, organization/role checks, transactional audits and tenant foreign keys |
| Vital observations | Manual fictional blood pressure/pulse, fixed sample readings, source/time/units, correction history, assigned-clinician writes, own-patient reads and signed-encounter locking |
| Updated demonstration | The existing complete-demo launcher enables fictional eligibility and the encounter/billing screens include the new controls |
| Regression coverage | Domain/API tests for deterministic fixtures, unknown benefits, failures/retries, permissions, CSRF, tenant isolation, persistence, stale context and immutable corrections; existing manual/billing/audio checks retained |

The previous code/coverage tests used a fixed October 10 expiry while expecting current evidence to remain valid. Their positive-evidence dates now use the current date plus seven days; explicit expired-evidence checks remain. This keeps regression results stable as time advances.

Validation: `npm test` passes **81 tests**. The complete launcher was smoke-tested successfully. An interactive browser screen check could not be completed because browser permission for the local app was declined; layout and browser interaction still need visual verification.

## Try the updated version in a few steps

1. Check out this update and run `npm run demo:complete` with Node 24+. The browser opens the local fictional app.
2. Use the physician sample account to open a patient encounter and record blood pressure/pulse or generate the fixed sample readings.
3. Use the billing sample account, open Billing, complete the fictional plan/code context and run an eligibility scenario. Review the separate benefit and coverage fields, then append a staff review.
4. Try `PARTIAL`, `INACTIVE` or `TIMEOUT`, change the service context, and inspect history. No test result becomes verified real coverage, an approved authorization or a payment.

All three sample accounts use `DemoOnly!ChangeMe123`: `doctor@example.test`, `biller@example.test`, `patient@example.test`. Use only fictional inputs. The separate public Railway concept is unchanged by the local launcher and does not expose this authenticated workflow. This code update does not deploy or merge itself.

## Current platform scope and next work

| Capability | Current state / remaining work |
| --- | --- |
| Chart, visit sections, signed encounter, private files and portal | Existing authenticated foundation; production security, retention and operational validation remain |
| Appointment-sourced coding and detailed toxin administration | Existing source-linked service/code review; official licensed CPT data and complete payer-specific coding edits still require integration |
| Scheduling, care handoff and rooming | Public concept demonstrations exist; the local Schedule page is a list, not a complete production scheduling/rooming service |
| Claims, denial records and correction simulations | Existing local claim queue and fictional clearinghouse; no actual claim transmission or authenticated remittance |
| Eligibility and benefits | Added test adapter and durable records; live insurer/clearinghouse connection remains disabled |
| Blood pressure and pulse | Added observation/history workflow; live device acquisition and continuous monitoring remain unimplemented |
| Prescribing, pharmacy, laboratory/radiology exchange | Not implemented; requires approved vendor interfaces, identity/access controls and clinical workflow validation |
| Complete EHR operations | Full medication reconciliation, clinical decision support, result routing, interoperability, consent, backup recovery, hardened auth and clinical safety validation require additional implementation |

Next delivery order: select/validate a device and its ingestion contract; complete authenticated scheduling/rooming and results workflows; implement authorized eligibility/claims integrations and reviewed payer-specific rules; then complete production security/clinical validation. No real-patient launch is enabled by this update.
